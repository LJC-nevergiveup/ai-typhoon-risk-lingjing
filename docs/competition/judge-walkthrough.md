# 评委走查记录（模拟一位完全不了解项目背景的评委）

> 走查方法：以一位第一次打开作品、对项目背景一无所知的评委视角，按 **01 → 06**
> 章节顺序逐章走查。每章只花 **10–30 秒**，重点回答一个问题：**评委是否知道这章想
> 告诉他什么**（而不是"按钮能不能点"）。
>
> 事实依据（本文件只依据以下真实内容撰写，未臆造）：
> `src/data/chapters.ts`、`src/components/InfoPanel/InfoPanel.tsx`、
> `src/data/layers.ts`、`public/data/real/yagi-2024/` 下各 manifest 与 sources。
>
> 冻结口径：默认进入 **REAL 案例「摩羯 YAGI」**，DEMO 仅为次级演示；
> 卫星 = FY-4B AGRI 观测；SST = NOAA Coral Reef Watch 日分析场（多源卫星融合，非单星瞬时观测）。

## 逐章走查

### 01 · 台风从哪来（origin）

| 字段 | 内容 |
| --- | --- |
| Core Question（核心问题） | 台风从哪里来？ |
| Core Message（核心信息） | 台风绝大多数在西北太平洋与南海热带洋面生成，需要海表温度通常高于 26.5℃ 的暖海水、水汽凝结释放潜热，以及地转偏向力（科里奥利力）让气流旋转成涡（赤道附近反而难生成）。 |
| Primary Interaction（主要交互） | 阅读"本节要点"4 条；在"本章专题·台风从哪来（三步走）"卡中可开启/关闭 SST 图层与卫星云图图层；查看 YAGI 首次记录（时间、坐标、等级）。 |
| Expected Takeaway（预期收获） | 记住台风生成三大条件：暖海温、水汽、地转偏向力；并意识到作品以真实案例 YAGI 作为例证起点。 |
| Observed Problem（观察到的问题） | 章节问题讲"通用成因"，专题卡却立即落到具体案例（Step 1 显示 YAGI 首次记录），存在"通用原理 → 具体案例"两层信息，快速阅读时可能混为一层；Step 2 的 SST 资料行显示"多源卫星融合（NOAA-20 VIIRS 等）"，与 Step 3"卫星看到了什么"（FY-4B 单星）在卫星口径上不同，评委若不细看标注可能把多源融合分析场误当单星瞬时观测。 |
| Status | **ok**（三大成因信息 10 秒内可读懂） |

### 02 · 台风往哪去（track）

| 字段 | 内容 |
| --- | --- |
| Core Question（核心问题） | 台风会往哪里去？ |
| Core Message（核心信息） | 台风不会"随意乱走"，移动主要受大尺度环流（尤其西北太平洋副热带高压）引导，常沿副高南侧向西—西北移动；预报不是一成不变，会随新观测滚动更新，远期存在"可能范围"。 |
| Primary Interaction（主要交互） | 阅读"本节要点"5 条与"本章专题·台风往哪去"要点；开启/关闭"移动机制示意"图层（副高椭圆 + 引导气流 + 转向气流）与"预测不确定性示意"图层（多条示意路径）。 |
| Expected Takeaway（预期收获） | 理解"副高是方向盘"与"路径预测存在不确定性"两个点。 |
| Observed Problem（观察到的问题） | 本章要点提到"集合预报（概率面条图）"，但实际展示的是"预测不确定性示意（非真实集合预报）"——两者概念相近，评委若不读图层标注，可能把示意路径误认为真实集合预报。UI 已明确标注"预测不确定性示意，非真实集合预报"，风险可控。 |
| Status | **ok**（核心信息明确，示意与非真实已充分标注） |

### 03 · 台风在哪登陆（landfall）

| 字段 | 内容 |
| --- | --- |
| Core Question（核心问题） | 台风会在哪里登陆？ |
| Core Message（核心信息） | 登陆点是路径与海岸线的交点，决定受灾的第一现场；登陆时间（是否与天文潮叠加）、登陆时强度（风速/气压）、风圈与风雨影响共同决定破坏力。 |
| Primary Interaction（主要交互） | 阅读"本节要点"6 条；查看"登陆过程"卡（YAGI 两次登陆：海南文昌翁田镇 08:20 UTC、湛江徐闻角尾乡 14:20 UTC，含强度/最大风速/中心气压）；地图叠加 track + landfalls 图层。 |
| Expected Takeaway（预期收获） | 知道 YAGI 有两次真实登陆及对应强度数值（62 m/s / 915 hPa；58 m/s / 925 hPa）。 |
| Observed Problem（观察到的问题） | 本章要点列了"风圈（七级/十级/十二级风圈）"，但风圈数据当前为 `awaiting-authoritative-data`（`wind-radii.geojson` 为空占位、未伪造），评委若在本章寻找风圈可视化会落空。"数据状态"卡中"风圈"计数显示"—"、并有 warning 提示，但需评委下拉到底部才会看到。 |
| Status | **needs-manual-check**（"风圈"要点与数据缺失之间的落差，需人工确认是否影响评委对本章完整性的判断） |

### 04 · 哪里更危险（risk）

| 字段 | 内容 |
| --- | --- |
| Core Question（核心问题） | 哪些地方更危险？ |
| Core Message（核心信息） | 用"低洼地形 + 人口暴露 + 路径邻近度"三个因子，按**确定性、可审计的规则**（非权重调参）叠加出"重点关注 / 较高关注 / 一般关注"三级提示；这是**科普型空间分析，不属于官方灾害风险预报**。 |
| Primary Interaction（主要交互） | "本章专题·哪里更危险（四步）"卡逐层开启地形/人口暴露/路径邻近度/空间关注提示四个图层；点击"定位到分析区"飞到黄色虚线框（海南北部—琼州海峡—雷州半岛）；在框内点击任意位置弹出"点击查询·空间关注提示"（海拔、地形关注、人口暴露、距路径距离、空间提示、免责声明）。 |
| Expected Takeaway（预期收获） | 理解风险空间差异来自多因子叠加，且结论只是"科普提示"，实际防灾以官方预警为准。 |
| Observed Problem（观察到的问题） | 本章信息量是六章中最大（四步 + 点击查询 + 多图层 + 多处免责声明），10–30 秒内评委通常只能抓住"三因子 → 关注分级"主线；"点击查询"这一核心交互依赖评委在黄色虚线框内主动点击，若评委只看不动，会漏掉点击查询入口。免责声明与口径说明充分、严谨。 |
| Status | **ok**（主线清晰），建议走查时主动演示一次"框内点击查询"，确保评委看到该交互。 |

| 字段 | 内容 |
| --- | --- |
| Core Question（核心问题） | AI 能帮我们做什么？ |

### 06 · 人该怎么做（action）

| 字段 | 内容 |
| --- | --- |
| Core Question（核心问题） | 我们应该怎么做？ |
| Core Message（核心信息） | 防灾行动要分情境：沿海地区（远离海岸、不观浪追风）、低洼城区（防内涝、不涉水）、山区（远离沟谷陡坡、警惕山洪滑坡）、家中（关门窗、备物资）；同时备好应急包，**一切行动以官方预警为准**。 |

| Expected Takeaway（预期收获） | 记住"看懂预警 → 提前转移 → 远离危险区 → 备应急物资"，并知道"以官方预警为准"。 |
| Observed Problem（观察到的问题） | 无交互图层、纯清单式阅读，核心信息直白无理解障碍；唯一注意点是"先看官方预警"的免责声明位于卡片底部，评委快速滚动时可能略过，但故事收尾语又重复了"以官方预警为准"，形成兜底。 |
| Status | **ok**（行动信息直白，官方预警口径多处重复） |

## 整体走查结论

六章由"成因 → 路径 → 登陆 → 风险 → AI → 行动"串成一条连贯故事线，每章的核心问题与核心信息都足够直白，一位不了解背景的评委通常能在 10–30 秒内理解"这一章想告诉他什么"；**唯一需要人工复核的是 03 章"风圈"要点与数据缺失（awaiting-authoritative-data）之间的落差，以及 04 章"框内点击查询"这一核心交互是否被评委实际触发看到。**
