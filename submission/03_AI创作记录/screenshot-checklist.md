# 截图候选清单（AI 创作记录佐证）

> 用途：为“AI 辅助 ≠ AI 自主得出结论”与真实人工审核过程提供屏幕佐证。
> 规则：**最终比赛至少选 2 张；严禁伪造历史截图**。若历史 Codex 会话仍可打开，优先截取与下方 4 项
> 对应的最有价值的一屏；截图由人工从真实会话补录，放入 `screenshots/`（当前暂空，见该目录 README.md）。

## 候选 1 · Codex 早期项目搭建（Prompt + 输出）

- **对应轮次**：Round 1 · 工程初始化与基础 UI
- **期望画面**：会话中关于“从零初始化 Vite + React + TypeScript + MapLibre + ECharts、六章节单页导航、PC 优先”的任务要求（Prompt）与 AI 生成的工程骨架 / 组件代码输出同屏。
- **说明要点**：体现“AI 按人工约束搭建工程骨架，人工随后 typecheck / build 验证”的分工。

## 候选 2 · 真实 YAGI 数据接入 / QA

- **对应轮次**：Round 2.5 · YAGI 真实轨迹接入
- **期望画面**：会话中台风网官方 API 数据解析、36 时次 QA 摘要（点数 / 时间范围 / 风速 13–62 m/s / 气压 915–1004 hPa / 0 缺失）或 `import-nmc-track.ts` 的 `--self-test` 输出。
- **说明要点**：体现“官方数据 → 脚本 QA → 人工交叉核验”的可追溯链路。

## 候选 3 · nmcFlagRaw 人工审核过程

- **对应轮次**：Round 3 · 登陆证据链（字段审计）
- **期望画面**：会话中关于原始字段 8 语义无法证实、拒绝当作“官方登陆标记”、改名为 `nmcFlagRaw` 的讨论与代码 / 数据改动。
- **说明要点**：这是“AI 不自主得出结论、发现可疑字段交人工裁决”的最直接证据，优先入选。

## 候选 4 · 风险空间分析 / QA

- **对应轮次**：Round 5（风险分析）或 Round 6.5（一致性清理重跑）
- **期望画面**：`prepare_terrain.py` / `prepare_population.py` / `compute_track_proximity.py` / `build_risk_awareness.py` 的 QA 输出，或关注分级计数（重点关注 1,562 / 较高 36,762 / 一般 39,876）与数据源变更（WorldPop → Kontur）记录。
- **说明要点**：体现“derived analysis 由确定性规则脚本生成、数值经人工审阅、来源变更如实记录”。
